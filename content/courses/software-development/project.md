## The situation

Brian runs a barbershop in Kakamega. Customers queue for hours because bookings are done by phone call. He would like a simple web page where a customer can see services and send a booking request. You will act like a real developer: plan the work, build a tiny first version, track it in Git and publish it. The app is for a **made-up shop**.

> **Note:** Use made-up customers, phone numbers and prices. Do **not** put real personal data, passwords or API keys in your code or GitHub repository.

## What you will produce

1. **Requirements** – five user stories in the form "As a… I want… so that…", and acceptance criteria (Given/When/Then) for the two most important ones.
2. **Design** – a paper or Canva wireframe of the main screen and a flowchart for one action (such as booking) with at least two decisions.
3. **A small working build** – one page (HTML, CSS and a little JavaScript or Python) that shows at least three services and one working feature, for example a booking form that shows a confirmation message, or a function that calculates the total of chosen services. Include **at least four tests** for one function (normal, boundary, zero, wrong input).
4. **Version control** – a GitHub repository with a README (what it does, how to run it, what you learned) and at least **five commits** with clear messages.
5. **Published link** – the page live on GitHub Pages or another free static host.
6. **Reflection** – 100–150 words: one bug you found, how you fixed it, and what you would build next sprint.

## Steps

1. Write your user stories before you code anything.
2. Draw the wireframe and flowchart. Take a clear photo or export them.
3. Build the smallest version that works, committing after each small step.
4. Write and run your four tests. Fix what fails.
5. Publish it, open it on your phone, and ask a friend what looks confusing.
6. Fix one thing and push again.

## What to submit

- A **link** to your GitHub repository and your live page.
- In the text box: your user stories, the test results and your reflection.
- Optional: upload your wireframe and flowchart as PNG, JPG or PDF (max 5 MB).

## Tips

- A small app that works beats a big one that does not.
- Commit messages like "Add booking form" help reviewers follow your story.
- Peers cannot see your laptop, so check the live link works in a private browser tab before submitting.

```rubric
User stories and criteria | Five well-formed user stories and two clear acceptance criteria that match the app | 4
Design | Wireframe and flowchart are readable, match the build and the flowchart has two or more decisions | 3
Working build and tests | The live page works, one real feature is visible and four sensible tests are shown | 6
GitHub and README | At least five meaningful commits and a README that explains the project | 4
Reflection | 100–150 words naming a real bug, the fix and a next step | 3
```
